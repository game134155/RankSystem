# 后端实现说明

## 整体分层

后端采用 **Servlet 处理 HTTP + JDBC 访问数据**，中间用简单的 **JavaBean / Map** 传数据，刻意不用大型 MVC 或 ORM，便于看清「一次请求里发生了什么」。

大致分工：**Servlet** 管路由、会话、取参、鉴权与跳转；**DAO** 管 SQL 与事务；**工具类** 管连接与密码哈希。

## Servlet 与请求流

- **`@WebServlet`** 声明 URL（如 `/login`、`/player/dashboard`），与 `web.xml` 里欢迎页等配置并存。
- **GET** 多用于打开页面或带查询条件的只读操作；**POST** 用于登录、提交比赛等会改数据的操作。
- 登录成功后把 **`User`（不含密码）** 放进 **HttpSession**，后续页面根据 Session 判断是否已登录、是否管理员，未通过则重定向到登录页。

## 认证与权限（原理）

登录时用 **`player_id` 查库**，对输入密码做 **SHA-256** 后与库中 `password_hash` 比较；一致则建立会话。管理员专属接口在 Servlet 入口再次判断 **`is_admin`**，避免仅靠前端隐藏按钮。

查询统一用 **PreparedStatement**，把「结构与数据」分开，降低 SQL 注入风险；防注入与密码哈希解决的是不同问题，两者互补。

## DAO 与数据访问

- **`AuthDao`**：只负责「能否登录、返回谁」。
- **`PlayerDao`**：按玩家拉 **多游戏排行视图**、**对局历史**（可带游戏名过滤）、以及 **游戏列表**（给下拉框用）。实现上通过多表连接，把数据库里的规范化结构转成页面需要的「宽表」信息。
- **`AdminDao`**：管理员维度的列表查询；核心是 **录入一场 5v5**：校验人数与用户名、解析游戏与玩家、算 MMR 变化、写对局主表与每人一行明细、更新统计表。这些写操作放在 **同一连接、关闭自动提交** 的事务里，成功则提交，任一步失败则回滚，避免出现「只记了半场比赛」的不一致。

## MMR 与段位（思路级）

赛前读取各玩家在该游戏中的 MMR，按 **两队平均分差** 套一个简化公式，得到胜方加分与败方扣分（并设有下限，避免变化过小）。赛后根据新的 MMR 在 **段位配置表** 里反查当前应属段位，写回统计表。具体公式以实现代码为准，文档只强调：**规则集中在后端、与展示解耦**。

## 配置与连接

数据库地址、账号等集中在 **`DBUtil`**，部署时改一处即可。JDBC URL 上可附带时区、SSL、公钥检索等参数，以适配本机 MySQL 8 的常见连接方式。
