# 前端实现说明

## 技术形态

浏览器侧主要是 **HTML 表单 + JSP 服务端渲染**，样式集中在 `css/style.css`。不单独拆前后端工程，页面由 Tomcat 在服务端拼好 HTML 再返回。

## 入口与路由习惯

- **`index.jsp`**：只做一件事——把用户重定向到登录地址 `/login`，避免根路径空白或散落多个入口。
- **业务 JSP** 放在 **`WEB-INF/jsp/`**：浏览器不能直接输入 URL 打开，必须由对应的 **Servlet 转发（forward）**，这样所有页面都先经过后端，便于统一鉴权与准备数据。

## 各页面在做什么

- **登录页**：表单 POST 到 `/login`，收集数字型 `player_id` 与密码；错误信息由后端放进 `request` 再转发回来显示。
- **玩家仪表盘**：展示当前（或管理员指定的）玩家的多游戏段位表、对局历史；历史支持按游戏名下拉筛选，本质是带查询参数的 GET 请求。管理员从管理台点「查看」会带上 `playerId`，与「只看自己」共用同一套页面。
- **管理台**：列表展示全部账号，提供进入玩家详情的链接；下方是录入一场 5v5 的大表单，POST 到 `/admin/add-match`。成功或失败通过 **重定向 + URL 参数 / Session 里的一次性提示** 反馈，避免刷新导致重复提交。

## 与后端的协作方式

前端不直接访问数据库：只负责 **把用户操作变成 HTTP 请求（GET/POST 与参数）**，展示后端放进 **`request` / `session`** 的数据。这样职责清晰——展示与跳转在前端 JSP，规则与数据在后端。

## 样式与资源路径

静态资源用 **`request.getContextPath()`** 拼前缀，保证应用部署在子路径（非 `/`）时，CSS 与表单提交的地址仍然正确。
