## 二、成员 A — 第 1 分钟（0:00～1:00）

**主题**：项目是什么、用什么技术、如何跑起来。

### 画面与操作

1. （可选）片头 3 秒：项目名称「Game Ranking System / 游戏排位信息系统」。
2. 打开 IDE 或资源管理器，**快速扫一眼**目录：`src/main/java`、`src/main/webapp`、`sql/`（各停约 1 秒，不必逐文件点开）。
3. 终端显示已执行：`mvn jetty:run`（或切到浏览器证明服务已起）。
4. 浏览器打开登录页 `http://localhost:8080/`，**停留 2～3 秒**让观众看清标题与页面布局。

### 口播稿（约 55～60 秒）

> 大家好，我们是××小组。本项目是一个**多游戏玩家排位与对局管理系统**，用于课程数据库作业。  
> 技术栈采用 **Java Servlet + JSP + JDBC** 做后端，**MySQL** 存数据，前端是 **HTML/CSS**，通过 **Maven Jetty** 或 Tomcat 部署运行。

> 代码按分层放在 `dao`、`model`、`web` 等包中，数据库脚本在 `sql` 目录。启动前用脚本一键重置数据库，再执行 `mvn jetty:run` 即可访问。

## 三、成员 B — 第 2 分钟（1:00～2:00）

**主题**：库表设计与表间关系（体现数据库课要求）。

### 画面与操作

1. 打开 `sql/schema.sql`（或 MySQL Workbench / 命令行 `USE ranking_system; SHOW TABLES;`）。
2. 依次**高亮或滚动到**（每表约 8～10 秒）：
   - `player` — 用户与管理员标志、密码哈希
   - `game`、`rank_tier` — 游戏与段位阈值
   - `player_stats` — 玩家在某游戏的 MMR、胜负、当前段位
   - `match_history`、`match_player_result` — 一场对局与 10 名队员结果
   - `announcement` — 公告
3. （可选）用一句话指向外键：`player_stats` 关联 `player`、`game`、`rank_tier`。

### 口播稿（约 55～60 秒）

> 大家好，我是 **[姓名]**，负责数据库部分。  
> 我们将数据拆成**多张规范化表**：`player` 存账号，密码以 **SHA-256 哈希**保存，不用明文；`game` 和 `rank_tier` 描述每个游戏及其段位门槛；`player_stats` 用复合主键记录**每位玩家在每个游戏**的 MMR、胜负场次和当前段位。  
> 对局方面，`match_history` 记录一场比赛元数据，包括比赛类型 Casual、Normal、Peak；`match_player_result` 存十名队员的胜负、MMR 变化前后值，满足「一场 5v5、十条明细」的业务需求。  
> `announcement` 单独存公告，通过外键关联发布者。  
> 初始化用 `schema.sql` 建表、`seed.sql` 灌入测试数据，应用层通过 JDBC 访问，**不使用 ORM**。  
> 下面由 **[成员 C 姓名]** 演示玩家端功能。

### 注意

- 不必念完整 DDL，**讲清「谁存什么、为什么拆表」**即可。
- 若用 Workbench，提前开好 ER 图或表列表，避免现场卡顿。

## 五、成员 D — 第 4 分钟（3:00～4:00）

**主题**：管理员 — 后台总览、录入 5v5 对局、验证 MMR 更新。

### 画面与操作（按顺序）

1. 登录页：Player ID `1`，Password `admin123` → 进入系统。
2. 打开 **Admin Dashboard**，**快速掠过**：
   - Add Player / Add Game 表单（各停 1 秒，口播一句带过）；

3. 回到 **Admin Dashboard**，聚焦 **Add 5v5 Match**：

   - Match Type：选 `Normal Match (MMR ×1)`
   - Winner 5 人：`alice`、`bob`、`cathy`、`david`、`emma`

4. 在 All Players 中再次 **View** `alice`（或刚才胜方任一玩家），展示 **MMR / Wins 已变化** 及 **Match History 新增一行**。

### 口播稿（约 55～60 秒）

> 大家好，我是 **[姓名]**，演示**管理员端**。  
> 使用管理员账号 player_id 1 登录后，进入 Admin Dashboard，可以添加玩家、添加游戏及段位配置，并在列表中维护全部用户。  
> 核心是**录入一场 5v5 对局**：选择游戏与比赛类型，例如 Normal 为正常 MMR 倍率，Peak 为三倍，Casual 只记胜负不改 MMR。  
> 填写胜方与负方各五个用户名后提交，系统在**同一事务**中插入 `match_history`、十条 `match_player_result`，并更新每位玩家的 MMR、胜负场次和段位；任一步失败会**整体回滚**。  
> 我们刚录入了一场比赛，现在查看 alice 的面板，可以看到 MMR 与胜场增加，对局历史也多了一条记录。

## 六、成员 E — 第 5 分钟（4:00～5:00）

**主题**：公告发布、安全与后端要点、收尾。

### 画面与操作

1. 顶部进入 **Announcements**。
2. 在 **Publish Announcement** 文本框输入一句演示公告，例如：  
   `Demo: Season ranking update is live. Good luck!`  
   点击 **Publish**，列表顶部出现新公告。
3. （约 15 秒）打开 `src/main/java/com/rankingsys/util/PasswordUtil.java` 或 `AuthDao.java`，**滚动露出**密码哈希比对或 SHA-256 相关代码（不需逐行讲解）。
4. （可选）打开 `AdminAddMatchServlet.java` 或 `AdminDao.java`，指向「transaction / commit / rollback」关键字。
5. 回到浏览器登录页或项目 README，**结束定格 2 秒**。

### 口播稿（约 55～60 秒）

> 大家好，我是 **[姓名]**。  
> 管理员可以在公告页**发布公告**，所有用户登录前后都能查看；普通玩家没有发布入口，这体现了**基于角色的访问控制**。  
> 安全方面，密码在入库前做 **SHA-256** 哈希，登录时对用户输入做同样哈希再比对，避免明文存储；数据库访问使用 **PreparedStatement**，降低 SQL 注入风险。  
> 后端采用经典 **Servlet + DAO** 结构：Servlet 处理请求与 Session，DAO 封装 SQL；录入对局等写操作在 **JDBC 事务**中完成，保证数据一致性。  
> 本项目完成了多游戏排位、5v5 对局录入、MMR 与段位自动更新、公告与权限管理等需求，技术栈符合课程对 JDBC 与关系型数据库的要求。  
> 演示到此结束，感谢观看！

## 八、常见问题与应急

| 情况 | 处理 |
|------|------|
| 登录失败 | 确认 `reset-db` 已执行；ID 与密码与 seed 一致 |
| 添加对局报错「用户不存在」 | 检查用户名拼写；必须已在 `player` 表中 |
| 端口占用 | 修改 Jetty 端口或关闭占用 8080 的进程 |
| 单人超时 | 压缩「Add Game / 注册」等非必演示步骤 |
| 录屏卡顿 | 关闭 IDE 索引、杀毒实时扫描；提前录一段备用 B-roll |
